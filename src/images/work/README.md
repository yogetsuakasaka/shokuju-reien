# src/images/work/ — 写真のアップロード先

**iPhone から写真をアップロードするのは、このフォルダです。**

ここに置いた画像は、そのままサイトに出るわけではありません。
`npm run images` が、ここから各スロット用の画像を切り出して `src/images/` の下に書き出します。

---

## iPhone からのアップロード手順

### 1. 位置情報を外す（必ず）

**このリポジトリは公開されています。** 写真の EXIF には GPS 座標が入っているため、
そのままアップロードすると撮影場所が誰にでも分かる状態になります。

1. 写真アプリで写真を開く
2. 共有ボタン（□に↑）をタップ
3. 上部の **「オプション」** をタップ
4. **「位置情報」をオフ** にする
5. 「完了」→「"ファイル"に保存」

> Android の場合：共有 →「位置情報を削除」

**外し忘れても大丈夫です。** `npm run build` が EXIF を検出してビルドを止めます
（`scripts/check-exif.mjs`）。ただし、その時点でコミット済みだと履歴に残ってしまうので、
**アップロード前に外すのがいちばん確実**です。

### 2. サイズを整える

| 用途 | 長辺 |
|---|---|
| Hero 候補（トップ最上部に使うかもしれない写真） | **4000px** 程度 |
| それ以外 | **3000px** 程度 |

- Hero のスマホ用は 9:16 の縦を切り出すため、元が大きくないと解像度が足りません
- 6000px級の原本は置かないでください。**一度コミットすると履歴から消せません**
- iPhone の写真はそのままで概ね 4032px なので、通常はリサイズ不要です

### 3. ファイル名

半角英数字・小文字・ハイフンのみ。日本語と空白は使わないでください。

```
01-monument-hoshi.jpg
02-aerial-spring.jpg
03-plots-rows.jpg
04-circle-sakura.jpg
```

どのスロットに使うかは `scripts/image-recipes.json` で決めるので、
**ファイル名をスロット名に合わせる必要はありません。**

### 4. GitHub にアップロード

GitHub アプリ、または github.com のこのフォルダを開いて「Add file」→「Upload files」。

---

## アップロードしたあと

切り出し方（どこを残すか）を `scripts/image-recipes.json` に書いて、

```bash
npm run images:dry      # 何が作られるか確認（書き込みなし）
npm run images:apply    # 生成 + images.json への紐付け
npm run build
```

を実行します。**この作業は Claude Code に頼めます。**
「`02-aerial-spring.jpg` を Hero に使って」と伝えれば、切り出し位置の設定から
実画面の確認まで行います。

## このフォルダについて

- **ここの画像は公開ビルドには出力されません。**
  `Figure.astro` / `Hero.astro` の画像検索から除外してあります
- 切り出しをやり直せるよう、**ここの画像は消さずに残しておいてください**
- 出力される画像からは EXIF が自動的に除去され、sRGB プロファイルが付きます
  （iPhone の Display P3 写真の色がずれないようにするため）
- 色味（彩度・色相）は変更しません。必要な場合のみ、明るさとコントラストを
  自然に見える範囲で微調整します
